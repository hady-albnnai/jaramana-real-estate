## 3) 🎯 دروس منهجية مُكلفة (لا تكررها)

### أ) `dart format` لا يكفي — تكرر الخطأ مرتين
`dart format` يفحص **التركيب فقط**، ولا يكشف أخطاء الأنواع أو الاستيرادات المفقودة.

**الطريقة الصحيحة** (Flutter SDK غير متاح ⇒ `dart analyze` سيُظهر مئات أخطاء الحل الوهمية):
```bash
# قارن عدد الأخطاء ونوعها مع الأساس البعيد — لا خطأ جديد = سليم
git show origin/main:<file> > /tmp/base.dart
dart analyze /tmp/base.dart 2>&1 | grep "^ *error -" | sed 's/:[0-9]*:[0-9]* //' | sort | uniq -c > /tmp/base.txt
dart analyze <file>          2>&1 | grep "^ *error -" | sed 's/:[0-9]*:[0-9]* //' | sort | uniq -c > /tmp/cur.txt
diff /tmp/base.txt /tmp/cur.txt   # الفرق الوحيد المقبول = أسطر لمستنّا
```

### ب) 🔴 السبب الجذري المتكرر: `auth.uid()` = NULL
التطبيق يسجّل الدخول **بجلسة مخصّصة** (`staff_session_token`) لا بجلسة Supabase ⇒ `auth.uid()` تساوي NULL دائماً ⇒ **أي استعلام REST مباشر على جدول سياسته `auth.uid() = X` يُرجع صفر صفوف بلا خطأ** (فشل صامت).

- أُصلح في: `payments` · `ratings` · `users.ref_cnt` · `legal_consultations`
- **العروض تعمل** لأن سياستها فيها `i_pub = 1` يمرّ بلا `auth.uid()`
- **الحل النمطي:** Edge Function بمفتاح الخدمة

### ج) انحراف git بعد التجريد — الإجراء الناجح
```bash
git fetch origin
for f in $(git status --short | awk '{print $2}'); do
  diff -q <(git show origin/main:$f) $f >/dev/null 2>&1 && echo "SAME: $f" || echo "DIFF: $f"

# كلها SAME ⇒ git reset --hard origin/main
# فشل push بـnon-fast-forward ⇒ git rebase origin/main ثم push
```
