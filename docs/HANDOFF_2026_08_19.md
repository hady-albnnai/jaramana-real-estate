## 5. الخطوة المتبقية الوحيدة: نشر دالتي الـ Edge

على جهاز المالك (ويندوز) — نفس الأوامر المعتادة:

```bat
cd sweeda-real-estate-office-elc
git pull
powershell -ExecutionPolicy Bypass -File scripts\deploy_supabase.ps1 -PAT "sbp_..." -REF "vsgkgnjtebjxyqwpuopz"
```

- السكربت الآن: DELETE + POST لكل دالة (يصلح الـ 500) + يقبل 200/201 كنجاح.
- الـ migrations ستُعاد (idempotent — آمنة) والـ cleanup لن يحذف شيئاً (هناء
  نظيفة — الاستعلام سيعيد صفوفاً فارغة وبأعداد 0).
- **المؤشر على النجاح:** `Create admin-dashboard [POST] HTTP 201` ثم
  `Create legal-actions [POST] HTTP 201` ثم `[DONE] All steps completed successfully.`

> بديل: أي وكيل لديه وصول للـ API مباشرة (إن فُتحت الشبكة) ينفذ نفس السكربت
> من bash: `APPLY_MIGRATIONS=true CLEANUP=false DEPLOY_FUNCTIONS=true bash scripts/deploy_supabase.sh`.

## 7. أمور تقنية حاسمة (اقرأها قبل أي تعديل)

### نموذج الاستشارة V2
- **الجلسة هي مصدر الحقيقة للوقت** (`consultation_chat_sessions`):
  `ready → join_window → active → ended`. حقول `chat_started_at`/`chat_duration_minutes`
  في `legal_consultations` موروثة (Legacy) — تحدّثها `join_chat_session_v2` و`advance/sync` فقط.
- سلسلة اعتماد الدفع الفعلية: `admin → approve_payment_final_v5 → v4 → v3`.
  **`v3` هو من ينشئ جلسة التجديد** (`renewal ready` + رسالة system + إشعار محامٍ)
  — لا تُضف هذا المنطق في أي تريغر (تكرار = ازدواج إشعار).
- `sync_chat_session_v2` يُستدعى في بداية كل إيدج (get_chat_messages/session/
  send) — يحوّل join_window منتهي المهلة وactive منتهي المدة فوراً.

### بنية التحديث اللحظي (قرار معماري)
- **لا Realtime يعتمد عليه** لجدول `notifications` (بلا RLS عام) ولجلسات
  موظفي الهاتف (بلا JWT) ⇒ الاستطلاعات الخفيفة هي الأساس:
  - شاشة الحجز: 20 ث · الشات: 20 ث (للمستخدم غير المحامي على ready/timeUp/pending)
  · لوحة المحامي: 30 ث · شاشات الإدارة: 45 ث · الرئيسية: 45 ث.
  - كل الاستطلاعات تُلغى في `dispose` — تعمل فقط أثناء فتح الشاشة.
- `NotificationProvider.refreshSignal` (إشارة ثابتة) — يطلقها FCMService عند
  وصول Push، وشاشة الإشعارات تستمع فتُحدَّث فوراً.

### دروس النشر/السكربت (لتجنب تكرار معاناة المالك)
- **ملفات `.ps1` يجب أن تكون ASCII خالصة** — أي حرف عربي يكسر PowerShell 5.1
  (حتى مع BOM). الاسم العربي يُمرَّر base64.
- **HTTP 201 = نجاح** في Supabase Management API (وليس 200 فقط).
- **ترتيب الحذف في التنظيف:** lawyer_earnings ← payments (FK).
- **نشر الدوال عبر DELETE+POST** — PATCH يفشل بـ 500 عند `import_map_path:null`.
- التوكن `sbp_...` سُرب في الشات — المالك عُلم بضرورة تغييره بعد النشر.
- بيئة الساندبوكس تحجب supabase.com (TLS يُقطع) — النشر من جهاز المالك فقط
  أو GitHub Actions (ملف المثال: `scripts/deploy-supabase-workflow.yml.example`
  يتطلب سر `SUPABASE_PAT`).

## 8. خطة الاختبار بعد اكتمال النشر (مسار التجديد من الصفر)

1. مستخدم جديد → استشارة هاتفية → دفع → «قيد المراجعة» تظهر فوراً.
2. الإدارة تعتمد → ينتقل المستخدم تلقائياً لنموذج الموضوع → إرسال → محامٍ
   يقبل → جلسة ready → المحامي «أنا جاهز» → مهلة دقيقتين → عداد 15 دقيقة.
3. انتهاء العداد → حوار الخيارات **مرة واحدة** → «تجديد» → دفع 500 →
   «قيد المراجعة» مع زر «فتح المحادثة المرتبطة».
4. الإدارة تعتمد → **المحادثة تُفتح تلقائياً** (من الشاشة 6) أو تظهر
   «المحادثة جاهزة» (من الرئيسية) — **لا** نموذج جديد ولا دفع مكرر.
5. المحامي يستلم «🔄 تجديد مدفوع جاهز» → «أنا جاهز» → انضمام →
   عداد 15 دقيقة **جديد كامل** بنفس المحامي.
6. حالات إضافية: رفض الدفعة (إشعار + إعادة محاولة) · محادثة أقدم من 7 أيام
   (ممنوع التجديد) · محاولة دفع ثانية أثناء انتظار الأولى (ممنوعة).
