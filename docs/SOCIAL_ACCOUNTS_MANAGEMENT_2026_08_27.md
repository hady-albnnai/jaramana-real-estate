## 🎯 ما الذي تغيّر؟

قبل هذا التاريخ كان النشر التلقائي يعتمد على **مفاتيح بيئة ثابتة** على السيرفر
(`META_FACEBOOK_PAGE_ID` / `META_PAGE_ACCESS_TOKEN` / `META_INSTAGRAM_ACCOUNT_ID`)
تُضبط يدوياً من terminal ولا يمكن تغييرها إلا من المطور.

الآن: **أي عدد من الحسابات** (صفحات فيسبوك + حسابات إنستغرام المهنية) يُضاف
ويُعدّل ويُحذف **من داخل التطبيق** — شاشة «حسابات النشر الاجتماعي» في لوحة
الإدارة (صلاحية: إعدادات التطبيق / دور ≥ 5 مدير أو نائب) — والناشر يوزّع كل
عرض مقبول على كل الحسابات المفعّلة.

```
┌────────────────────────────────────────────────────────────┐
│ المدير ← شاشة «حسابات النشر» ← إضافة حساب (اسم + رقم +    │
│           توكن) ← تحقق تلقائي فوري من Meta                 │
└──────────────────────┬─────────────────────────────────────┘
                       ▼
┌────────────────────────────────────────────────────────────┐
│ جدول social_accounts (توكنات محمية بـ RLS — service_role  │
│ فقط، لا تصل للعميل أبداً إلا مقنّعة بآخر 4 محارف)          │
└──────────────────────┬─────────────────────────────────────┘
                       ▼
┌────────────────────────────────────────────────────────────┐
│ المدير يقبل عرضاً مفعّلاً به «النشر على السوشيال»          │
│ (admin-offers ← publishOfferToSocial)                      │
└──────────────────────┬─────────────────────────────────────┘
                       ▼
┌────────────────────────────────────────────────────────────┐
│ لكل حساب مفعّل: حجز ذرّي (claim_social_publication_v2) ثم │
│ نشر عبر Graph API ثم تسجيل النتيجة في social_publications │
└────────────────────────────────────────────────────────────┘
```

### القواعد الجديدة للنشر

| القاعدة | السبب |
|---|---|
| **لا نشر بدون صورة عامة واحدة على الأقل — لكل المنصات** (قرار المالك، متوافق مع بوابة IMG-001: «لا اعتماد لعرض بلا صورة») | جودة الإعلان العقاري: العرض بلا صور لا يُنشر، يبقى بالقائمة حتى تُضاف صورة |
| الصور تُنشر **كألبوم حتى 10 صور** مع نص العرض | Graph API: رفع الصور ثم تركيبها بمنشور واحد |
| فشل حساب واحد لا يمنع البقية | كل حساب مستقل بسجله الخاص |
| `soc_pub=2` فقط عند نجاح **كل** الحسابات | وإلا يبقى العرض في قائمة الجاهزة |
| إعادة المحاولة آمنة | حجز ذرّي لكل (عرض، حساب) يمنع التكرار |

## 📱 كيف تضيف حساب النشر (خطوات المالك)

### أول مرة: إنشاء تطبيق Meta والتوكن (مرة واحدة لكل صفحة)

التفصيل الكامل في `docs/SOCIAL_PUBLISH_SETUP_GUIDE_AR.md` (المراحل 1-2).
ملخّص سريع:

1. **developers.facebook.com** ← سجّل الدخول بحساب أدمن الصفحة ← Create App
   (نوع Business).
2. أضف منتج **Facebook Login for Business**.
3. افتح **Graph API Explorer** ← اختر تطبيقك ← Generate Access Token بالصلاحيات:
   `pages_show_list` + `pages_manage_posts` + `pages_read_engagement`.
4. مدّد التوكن (Long-Lived):
   ```
   https://graph.facebook.com/v25.0/oauth/access_token
     ?grant_type=fb_exchange_token
     &client_id=APP_ID&client_secret=APP_SECRET
     &fb_exchange_token=SHORT_LIVED_TOKEN
   ```
5. اجلب **Page Access Token الدائم** (لا ينتهي):
   ```
   https://graph.facebook.com/v25.0/me/accounts?fields=id,name,access_token
     &access_token=LONG_LIVED_USER_TOKEN
   ```
   وستجد في الرد صفحتك باسمها ومعها التوكن الدائم.

### داخل التطبيق (بعد النشر)

1. الإدارة ← أقسام الإدارة ← **حسابات النشر الاجتماعي** (أو: الإعدادات ←
   قسم «صفحات التواصل» ← حسابات النشر).
2. زر **إضافة حساب**:
   - المنصة: فيسبوك
   - الاسم: مثلاً «صفحة المكتب العقاري»
   - رقم الصفحة: `61592278445595`
   - التوكن: الصق Page Access Token الدائم
3. اضغط حفظ ← **يتحقق النظام فوراً** لدى Meta ويعرض اسم الصفحة الحقيقي:
   «✅ تم الحفظ والتحقق بنجاح: المكتب العقاري الالكتروني».
4. من هذه اللحظة: كل عرض يُقبل وفيه «النشر على السوشيال» مفعّل يُنشر تلقائياً
   على الصفحة.

### تجديد التوكن (عند انتهائه أو تغيير كلمة السر)

تعديل الحساب ← الصق التوكن الجديد ← حفظ (يتحقق تلقائياً). ترك حقل التوكن
فارغاً عند التعديل = الإبقاء على التوكن الحالي.

### التوافق الخلفي (مهم)

- إن لم يوجد أي حساب في `social_accounts`، يعمل الناشر بالمسار القديم
  (مفاتيح البيئة) كما كان — أي أن النشر لا ينكسر أبداً.
- عند وجود حساب واحد على الأقل في القاعدة **تُتجاهل مفاتيح البيئة**.
- صفوف `social_publications` القديمة (`account_id = NULL`) تبقى محفوظة كما هي.
- العروض ذات `soc_pub=2` لن تُنشر مجدداً (حارس `alreadyPublished` يسبق كل شيء)،
  فالانتقال من مفاتيح البيئة إلى الحسابات لا يسبب نشراً مزدوجاً.

### الأمان

- الجدول `social_accounts` تحت RLS **بلا أي سياسة للعملاء** + `REVOKE` صريح
  من anon/authenticated — الوصول حصراً عبر service_role (Edge Functions).
- التوكن **لا يعود كاملاً للعميل أبداً** — القائمة تعيد آخر 4 محارف وطوله فقط.
- سجل التدقيق `activity_log` بالأكواد 130 (حفظ) / 131 (تحقق) / 132 (حذف) —
  **بدون أي قيمة توكن**.
- تعديل الحساب بحقل توكن فارغ لا يمسّ التوكن الحالي.

## 🔍 المراقبة

```sql
-- حالة الحسابات
SELECT name, platform, account_external_id, is_verified, is_active, last_error,
       last_verified_at FROM social_accounts WHERE i_del = 0;

-- نتائج النشر لكل حساب
SELECT o.ttl, sa.name AS account, sp.platform, sp.status, sp.post_id,
       sp.error_message, sp.updated_at
FROM social_publications sp
LEFT JOIN social_accounts sa ON sa.id = sp.account_id
LEFT JOIN offers o ON o.id = sp.offer_id
ORDER BY sp.updated_at DESC LIMIT 20;
```

وأكواد التدقيق الجديدة في `activity_log`: `130/131/132`.

## 🧪 تغطية الاختبار (محفوظة للاختبار الفعلي)

- [ ] إضافة حساب فيسبوك صحيح → «موثّق ✓» + اسم الصفحة يظهر.
- [ ] إضافة حساب بتوكن خاطئ → يُحفظ لكن «غير موثّق» مع رسالة الخطأ من Meta.
- [ ] قبول عرض مفعّل بالنشر → منشور على الصفحة + `soc_pub=2`.
- [ ] عرض بلا صور → يُرفض النشر بالكامل (`PUBLIC_IMAGE_REQUIRED`) ويبقى بالقائمة الجاهزة.
- [ ] إعادة النشر لنفس العرض → «كان منشوراً مسبقاً» بلا تكرار.
- [ ] تعطيل الحساب → لا يُنشر عليه.
- [ ] حذف الحساب → يختفي من القائمة ولا يُنشر عليه.
- [ ] مستخدم دور < 5 → يُرفض (`INVALID_ADMIN_SESSION`).
