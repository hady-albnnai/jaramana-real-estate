## 1) قوانين غير قابلة للكسر (الدستور — `DEVELOPMENT_GUIDELINES.md`)

1. **التصميم قبل الكود، دائماً.** «حلّل»/«شو الحل؟» = تحليل بلا سطر كود. التنفيذ يبدأ فقط بعد موافقة صريحة («ابدأ»/«أوافق»/«تمام»). خطوة-خطوة، وتقرير مصغّر بعد كل قطعة.
2. **SQL المحصّن للّصق:** كل لصقة SQL = ملف migration مستقر فولاذياً قبل تسليمه: أوصاد متوازنة **بعد** إزالة تعليقات `--`، `$function$`/`$$` متطابقة، `WHERE`/حراس idempotent، و**كل لصقة تحمل تحقق SELECT قبل/بعد مدمجاً بداخلها**. الأرشفة: `supabase/migrations/YYYY_MM_DD_*.sql` — لا يُعدَّل بعد تنفيذه؛ التصحيح بملف جديد.
3. **رباعي التحصين لكل SECURITY DEFINER جديد:** ① `SET search_path TO 'public','extensions','pg_temp'` بالترويسة ② `REVOKE ALL ... FROM PUBLIC` ③ `REVOKE EXECUTE ... FROM anon, authenticated` ④ `GRANT EXECUTE ... TO service_role`.
4. **قاعدة النشر:** `git pull` **قبل** كل `supabase functions deploy <fn> --no-verify-jwt`. التوثيق مخصص staff_session — بوابة JWT ستكسر مستخدمي الهاتف.
5. **أسرار:** لا سر واحد يُكتب بملف بالريبو (عام!). الأسرار تنتقل Base64 من المالك وتُفك داخل الساندبوكس بمتغيرات شل فقط.
6. **الحقيقة الأرضية (§11):** لا تبني على مخرَج قديم/ملخّص ولا حتى على «نجاح» أداة كتابة. تحقق فوراً: `git log --oneline -3` · `git status --porcelain` · `grep -c` · `wc -l` · `git show HEAD:file | head`. مخرجات فاسدة وقعت فعلاً (كوميتات وهمية) — عند الشك، أعد الاستعلام بأمر مستقل.
7. **الانحراف ريبو↔سيرفر (§12):** أي لصقة/نشر بلا كومِت = دَين موثّق لحظياً ويُقفل بـ `supabase db dump`. حتى الإقفال: السيرفر = حقيقة التشغيل (افحص ضده)، الريبو = حقيقة المستقبل (ابنِ عليه).
8. **بروبات بلا إخفاء (§13):** سكربتات التحقق تُظهر أخطاء الحرّاس صراحة ولا تدفنها خلف `or []` (خطأ `USER_UID_REQUIRED` تنكّر يوماً بـ `slots=[]`). أي نتيجة «فارغة» ⇒ افحص أولاً أن الطلب مُقبول شكلاً.
9. **لعب الأدوار E2E:** أنت تمثّل كل الأدوار عبر API (حاجز↔مالك↔مشرف↔أدمن) بأرقام قبل/بعد موثقة. المرجع الحي: سلسلة موعد «يتيني» 2026-07-27 (أسفل §4).
10. **إعادة الحالة:** بعد كل سلسلة تحقق أعِد البيانات لنظافتها (استرجاع عناوين، عروض `sts=2/i_pub=1`، إلغاء مواعيد تجريبية بوسم سبب).
11. **البوش FCM لا يُثبت عن بعد إطلاقاً** — تسأل المالك «وصل؟». ما يُثبت عن بعد: صف الإشعار داخل التطبيق + سلوك RPCs.
12. **إيقاع الجلسة:** جداول مختصرة، لاصق واحد لكل خطوة، أسئلة حاسمة مجمعة، ختام = ملخص إنجاز + قائمة «على المالك» + تذكير التوكنات.
