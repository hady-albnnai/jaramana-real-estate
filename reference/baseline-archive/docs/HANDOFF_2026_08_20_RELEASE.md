## 2) المشكلة الأخيرة: الرسائل القصيرة (SMS OTP) — التشخيص الكامل

### ما رآه المالك
- الرسالة تُرسل من «الجهاز الذي عليه الشريحة» وليس من السيرفر مباشرة.
- الرسالة لا تصل فوراً، ومع ذلك يُخصم رصيد.
- تظهر رسائل لأرقام «لم تطلب الاشتراك».

### ما تأكد من الكود (الحقائق)
1. **البوابة TextBee**: `send-sms-otp` ترسل عبر `api.textbee.dev` الذي يوجّه الإرسال
   إلى **جهاز حقيقي مربوط بالحساب** (موبايل البوابة). هذا تصميم النظام نفسه وليس خللاً.
2. **الرقم المستهدف واحد فقط**: الكود يرسل حصراً `recipients: [normalizedPhone]`
   — لا قائمة أرقام ولا نسخ سرية. «الأرقام الثانية» إما رسائل قديمة متكدسة في
   طابور الجهاز انطلقت دفعة واحدة، أو مزامنة رسائل Google على موبايل آخر بنفس الحساب.
3. **سبب التأخير الأغلب**: موبايل البوابة نائم / برنامج TextBee مغلق أو مقيد
   بتوفير الطاقة / انقطاع النت — الطابور يتراكم ثم ينطلق دفعة واحدة.
4. **الخصم طبيعي**: كل رمز = رسالة واحدة؛ «إعادة الإرسال» = رسالة جديدة تُخصم.

### المطلوب من المالك (لحسم نهائي)
1. `git pull` ثم إعادة `drift_markers.ps1` ولصق سطر `[M-otp_recent]`.
2. فحص موبايل البوابة: شغول دائماً · برنامج TextBee مفتوح · مستثنى من توفير الطاقة ·
   مربوط بنت ثابت. (إن أمكن الاطلاع على سجل TextBee نفسه لرؤية كل رسالة إلى أين ذهبت.)

## 3) نقاش النشر والتوزيع — الملخص والقرارات

### الوضع مع جوجل بلاي
- الطريق الرسمي (جوجل بلاي) يمر عبر **شركة قديمة ناشرة** يملكها المالك — كل
  متطلباته موثقة في `docs/GOOGLE_PLAY_RELEASE_CHECKLIST_2026_08_20.md`
  (targetSdk 36 ✅ · صفحة حذف الحساب ✅ · Data Safety/IARC للشركة · بند الباقات ⚠️).
- المالك قرر **التوزيع المحلي أولاً** (APK مباشر) والاعتماد على **GitHub Releases
  كمصدر رئيسي** للتنزيل.

### ما تأكد عن الحماية (Play Protect)
- «تحقق المطورين» الإلزامي (30 أيلول 2026) يشمل **4 دول فقط** (البرازيل، إندونيسيا،
  سنغافورة، تايلاند) — سوريا خارجها، والتثبيت الجانبي متاح عادياً.
- لا يمكن «إزالة» تحذير Play Protect للتطبيقات خارج المتاجر، ولا توجد قائمة تبييض.
- روافع التخفيف الحقيقية: (1) 🔑 **مفتاح توقيع رسمي** بدل مفتاح debug الحالي —
  أهم خطوة؛ (2) سمعة التثبيتات مع الوقت؛ (3) تقرير VirusTotal نظيف يُعرض بالموقع؛
  (4) أجهزة هواوي الجديدة بلا Google أصلاً = صفر تحذير.
- **مخاوف المالك الحقيقية ليست «الشك» بل «عدم معرفة المستخدمين بالتثبيت»** —
  والحل هو الأدلة (البند التالي).

### قرارات المالك المسجلة
| القرار | الحالة |
|---|---|
| GitHub Releases = مصدر التنزيل الرئيسي | ✅ متفق |
| تصميم **دليل تنزيل** + **دليل استخدام** ينزلان مع التطبيق | ✅ متفق — الخطوة التالية |
| المربعات السوداء (صور فاشلة) بشعار المكتب | ✅ منفذ (13 موضع) |
| الباقات: عدم إيقافها (إيقافها يغيّر هوية التطبيق) | ✅ متفق — الصياغة الثلاثية مقترحة (بند 5 أدناه) |
| السر `SUPABASE_PAT` + النشر التلقائي | ⏸️ مؤجل اختيارياً |

### مقترح الباقات (ثلاث طبقات دفاع عند مراجعة جوجل)
1. Google Play Billing غير متاح بسوريا ⇒ بدائل الدفع مشروعة بالمنطقة.
2. الدفع يتم خارج التطبيق فعلياً (كاش/تحويل + إيصال + اعتماد يدوي) — التطبيق سجل لا صرّاف.
3. صياغة الباقات كـ«اشتراك خدمة الوساطة العقارية» + رد جاهز للمراجع.
   الخطة الاحتياطية: نقل شراء الباقة خارج التطبيق كلياً (واتساب/المكتب).

## 4) الأدلة المطلوبة — الخطة (الخطوة التالية الأولى)

### أ) دليل التنزيل والتثبيت (مصوّر، عربي، خطوة بخطوة)
1. فتح رابط التنزيل من الموقع/قناة تلغرام.
2. النقر على الملف المحمّل ← «تثبيت».
3. أول مرة: تفعيل «السماح من مصادر غير معروفة» (مع صورة إعدادات كل جهاز).
4. إن ظهر Play Protect: «تفاصيل ← التثبيت على أي حال» (مع صورة النافذة).
5. فتح التطبيق وإنشاء الحساب.
- **الصيغ:** صفحة بالموقع + PDF + داخل التطبيق (قسم «كيف أُثبّت؟» قبل تسجيل الدخول
  أو من شاشة تسجيل الدخول) + فيديو 30 ثانية يصوّره المالك لقناة تلغرام.
- **تقرير VirusTotal** يُربط بجانب زر التنزيل («فحص الأمان: نظيف 0/70»).

### ب) دليل الاستخدام (مختصر، فيديوات/صور لكل مسار)
1. إنشاء الحساب وتسجيل الدخول (OTP).
2. نشر أول عرض (خطوات + شروط القبول).
3. الباقات والنقاط والترقية.
4. طلب معاينة وحجز موعد.
5. الاستشارات القانونية (هاتفي/حضوري) والشات.
6. الدفع وإيصال الدفع والاعتماد.
7. خدمات المكتب (تصوير · تعقيب · سمسرة).
8. الأسئلة الشائعة.
- **مصدر وحيد قابل للتحديث:** يُستضاف الدليل في `docs/guide/` بالموقع (GitHub Pages)
  ويعرضه التطبيق داخل صفحة ويب — أي تحديث للدليل **بلا تحديث التطبيق**.

### ج) البنية التقنية المتفق عليها (تُنفذ بالترتيب)
1. 🔑 مفتاح توقيع رسمي على جهاز المالك (أمر جاهز) — يُحفظ بأمان (فقدانه = إعادة تثبيت
   يدوية لكل المستخدمين).
2. 🌐 صفحة تنزيل بالموقع + دليل التثبيت المصوّر.
3. 🐙 إعداد أول Release (سحب وإفلات الـ APK + رقم الإصدار).
4. 🔔 فحص تحديث داخل التطبيق يقرأ من GitHub («في نسخة جديدة — حمّلها»).
5. (مستقبلاً) Huawei AppGallery كقناة ثانية لأجهزة هواوي.

- **Ground truth:** البيئة قد تُعاد ضبطها — دائماً `git fetch origin` ثم
  `git reset --hard FETCH_HEAD` قبل أي عمل.
- **ملفات workflow:** الوكيل ممنوع من تعديلها (بلا صلاحية `workflows`) — أي تعديل

  GitHub ترفض الدفع — مجرّبة). السر `SUPABASE_PAT` يُضاف من Settings → Secrets.
- **ps1:** أي سكربت PowerShell جديد يجب أن يبقى ASCII خالصاً (ترميز UTF-8 يكسر
  PowerShell 5.1 في ويندوز المالك).
- **الدروس السابقة سارية:** أي SQL جديد = idempotent + تحقق مدمج + `zz` عند
  ضرورة التطبيق أخيراً + `DROP FUNCTION` قبل تغيير التوقيع + `staff RECORD;`.
