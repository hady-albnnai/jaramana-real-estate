## 🐞 الأعطال الجديدة

### BUG-012 🟠 — إبلاغ فشل بلا سبب في التوثيق (§13)

`admin_approve_verification_by_admin` و`admin_reject_...` تُرجعان `FALSE`
مجرّداً حين لا يكون المستخدم «قيد المراجعة»، وكان الإيدج يمرّر
`{"success": false}` **بلا أي حقل خطأ**.

**الأثر**: المدير يضغط «اعتماد» فلا يحدث شيء ولا يعرف السبب — هل الشبكة؟ هل
صلاحية؟ هل الطلب اختفى؟ لا شيء يخبره.

**الإصلاح**: `VERIFICATION_NOT_PENDING` + شرح عربي (409).

---

### BUG-013 🔴 — «رفض التوثيق» يجرّد أي حساب موثّق

```sql
-- قبل
UPDATE users SET vrf = 0 WHERE id = p_target_uid AND i_del = 0;
-- لا شرط على الحالة!
```

**الأثر**: استدعاء «رفض» على **أي** مستخدم — بما فيه حساب موثّق منذ شهور لم
يقدّم أي طلب — **يُسقط توثيقه** ويرسل له «تم رفض طلب التوثيق».

**الدليل الحي**: رُفض حساب حالته `vrf=2` ونجحت العملية وصار `vrf=0`.

**ملاحظة مهمة**: دالة **الاعتماد** كانت تحمل الشرط الصحيح (`AND vrf = 1`) —
**الرفض وحده أُغفل**. خلل غير متماثل يصعب ملاحظته بالقراءة السريعة.

**الإصلاح**: `AND vrf = 1`.
**بعد**: الموثّق ⇒ `VERIFICATION_NOT_PENDING` وحالته تبقى 2 · المعلّق يُرفض صحيحاً.

### BUG-014 🔴 — تسليم مهمة تصوير بصفر صور

```ts
if (!taskId || !Array.isArray(media))   // [] تمرّ!
```

**الأثر المزدوج**:
1. المصوّر «يسلّم» بلا أي صورة ⇒ المهمة تنتقل إلى «بانتظار المراجعة» ثم
   تُعتمد والطلب يُغلق **بلا وسائط إطلاقاً**.
2. **الأخطر**: بعدها يُرفض التسليم الصحيح بـ`TASK_NOT_FOUND_OR_NOT_ALLOWED`
   لأن الحالة لم تعد `1` ⇒ **المصوّر يفقد مهمته بلا رجعة** ولا يفهم لماذا.

**الدليل الحي**: `media:[]` ⇒ `success:true` · الحالة صارت `2` · `media = []`.
ثم التسليم الحقيقي بصورتين ⇒ **مرفوض**.

**الإصلاح بطبقتين**:
- الإيدج: ينظّف ويرفض الفارغ وحتى النصوص الفارغة (`""`, `"   "`)
- الدالة: `jsonb_array_length = 0 ⇒ MEDIA_REQUIRED`

**بعد**: 3/3 — `[]` مرفوض · `["","  "]` مرفوض · التسليم الصحيح ينجح.

### BUG-016 🟠 — مراجعة عرض غير موجود تُرجع نجاحاً + مخالفة §19

**(أ)** لا فحص وجود ⇒ `UPDATE` بلا صفوف لا يفشل ⇒ اعتماد عرض **بـuuid أصفار**
يُرجع `success:true`. المدير يظن أنه اعتمد شيئاً.

**(ب)** إعادة اعتماد عرض منشور سلفاً تُعيد النشر وتكرّر الإشعار.

**(ج) مخالفة §19**: 4 مواضع تستخدم كلمة **«عرضك»** المحظورة صراحةً في
الدستور، في نصوص إشعارات تصل للمستخدم فعلاً.

**الإصلاح**: `OFFER_NOT_FOUND` · `OFFER_ALREADY_PUBLISHED` · استبدال الأربعة
بـ«العرض الخاص بك».

**فحص شامل بعده**: صفر مخالفة §19 في **كل** دوال قاعدة البيانات ✅
