# 🔄 دليل تدفق المحادثة والتجديد — الواقع بعد تعديلات 2026-08-19

> هذا الدليل يصف كل الاحتمالات في مسار المحادثة القانونية وتجديدها،
> كما هو **بعد** التعديلات (الواجهة مرفوعة + السيرفر ينتظر النشر عبر
> `deploy-supabase.yml` أو الأوامر اليدوية). كل احتمال متابَع لآخره.

---

## 1️⃣ حالات المحادثة (جلسات V2)

| الحالة | المعنى | ماذا يرى المستخدم داخل الشات |
|---|---|---|
| `ready` | جلسة جاهزة بانتظار **المحامي** | «بانتظار استئناف المحامي» — قراءة فقط |
| `join_window` | المحامي جاهز — المستخدم لديه **دقيقتان** | «مهلة الانضمام …» — يدخل فيبدأ العداد |
| `active` | جلسة جارية | شريط إدخال + عداد تنازلي |
| `ended` | انتهت المدة | شريط «جدد» أو «⏳ دفعة قيد المراجعة» |
| بلا جلسة | لم تبدأ بعد (new) | «بانتظار استعداد المحامي» |

## 2️⃣ شجرة مسار التجديد (كل الاحتمالات)

```
المحادثة انتهت (ended)
│
├─ هل توجد دفعة تجديد معلّقة (sts=0) لهذه المحادثة؟ (pending_renewal)
│   │
│   ├─ نعم ──► شريط «⏳ دفعة تجديد قيد مراجعة الإدارة» (بلا زر دفع — لا دفعة مكررة)
│   │            + لا حوار خيارات + استطلاع كل 20 ث:
│   │            ├─ اعتُمدت ──► سيرفر: جلسة renewal جديدة (ready) + تمديد المدة
│   │            │                + رسالة system + إشعار المحامي «أنا جاهز»
│   │            │                └─► الشات يتحدث تلقائياً ← «بانتظار استئناف المحامي»
│   │            ├─ رُفضت ──► شريط «جدد» يعود + إشعار رفض + بطاقة دفعة مرفوضة
│   │            │             (إعادة المحاولة → prepare_rejected_payment_retry_v2)
│   │            └─ أُلغي/تُراجع عنه ──► يعود «جدد» (المحامي لا يُشعر بشيء)
│   │
│   └─ لا ──► شريط «جدد» + حوار خيارات (مرة واحدة فقط):
│              ├─ تجديد المحادثة ──► شاشة الدفع (intent phone_renew)
│              ├─ تحويل إلى حضورية ──► اختيار موعد + دفع الفرق
│              ├─ إنهاء وتقييم ──► نافذة التقييم
│              └─ لاحقاً ──► يبقى شريط «جدد»
│
├─ دفع التجديد (من الشات أو من «المحادثات السابقة»)
│   ├─ يوجد دفعة معلّقة لنفس النوع؟ ──► يوقفك عند شاشة «قيد المراجعة» (حارس)
│   └─ لا ──► إنشاء intent phone_renew + دفعة sts=0 (meta.continue_chat = المحادثة)
│            └─► شاشة «⏳ دفعتك قيد المراجعة» مع:
│                • زر «فتح المحادثة المرتبطة» (تقرأ رسائلها أثناء الانتظار)
│                • زر «تحديث الحالة» (بدون تصفير الشاشة)
│                • استطلاع تلقائي كل 20 ث:
│                  ├─ اعتُمدت ──► فتح المحادثة تلقائياً (SYNC-002) ← «بانتظار المحامي»
│                  ├─ رُفضت ──► بطاقة رفض + إعادة محاولة
│                  └─ ما زالت معلّقة ──► تبقى الشاشة (والشارة تتحدث)
│
├─ الاعتماد (الإدارة)
│   └─ سيرفر: جلسة renewal (ready, ordinal+1, payment_id) + chat_duration ممتد
│        + renew_count+1 + رسالة system «⏱️ تم تأكيد الدفع — تجديد X دقيقة»
│        + إشعار المستخدم + إشعار المحامي «🔄 تجديد مدفوع جاهز للاستئناف»
│        └─ الواجهة (حسب مكان المستخدم):
│           ├─ داخل شاشة 6 ──► ينتقل تلقائياً لفتح المحادثة
│           ├─ على الرئيسية ──► بطاقة «تم تأكيد دفعتك — المحادثة جاهزة» → زر «فتح المحادثة»
│           ├─ داخل الشات ──► استطلاع 20 ث → «بانتظار استئناف المحامي»
│           └─ في «المحادثات السابقة» ──► محادثة نشطة (متبقي > 0) → «متابعة المحادثة»
│
└─ دورة الجلسة الجديدة (بعد الاعتماد):
    ready
    └─► المحامي يضغط «أنا جاهز» ──► join_window (دقيقتان) + إشعار المستخدم
        ├─ المستخدم يدخل خلال الدقيقتين ──► active (يبدأ العداد فور دخوله)
        └─ لم يدخل ──► يبدأ تلقائياً (grace_expired) + إشعار للطرفين
            └─► active ──► (انتهت المدة) ──► ended ──► نعود لأول الشجرة
```

## 3️⃣ الاحتمالات الخاصة

### أ) محادثة أقدم من 7 أيام
- ممنوع تجديدها (`CHAT_EXPIRED_7DAYS`) — تُعرض للقراءة فقط، ولا تظهر في
  خيارات «المحادثات السابقة» القابلة للمتابعة (تظهر «منتهية»).

### ب) دفعة مرفوضة
- إشعار رفض + بطاقة «دفعة مرفوضة» ببطاقة السبب + زر إعادة المحاولة:
  `prepare_rejected_payment_retry_v2` → `retry_consultation_payment_v2`
  (نفس المحادثة، دفعة جديدة sts=0) → نفس شجرة الانتظار.

### ج) عكس الاعتماد (إداري)
- جلسة renewal (`ready`) تُعكس → `reversed` → المحادثة تعود `ended` →
  يظهر «جدد» من جديد. وإذا كانت الجلسة استُهلكت (active/ended) يرفض العكس.

### د) المحامي
- لا يضغط «أنا جاهز»؟ تبقى الجلسة `ready` بلا مهلة على المحامي — المستخدم
  يرى «بانتظار استئناف المحامي» ولا يمكنه الكتابة حتى يبدأ المحامي (لا عداد
  يعمل قبل ذلك). وهذا مقصود: «وقت المحامي» لا يُحتسب إلا بعد استئنافه.

### هـ) استشارة جديدة (وليست تجديداً)
- دفعة بلا `continue_chat` → بعد الاعتماد → نموذج «موضوع الاستشارة» →
  إرسال → إسناد محامٍ جديد (`pick_next_lawyer`) → جلسة أولى `ready`.

### و) زر «متابعة إحداها» في «المحادثات السابقة»
- محادثة **نشطة** (مدة ممتدة من تجديد معتمد، متبقي > 0) → زر «متابعة المحادثة»
  يفتح الشات مباشرة — **لا** دفع مكرر (كان يفتح دفع الألف رغم القبول).
- محادثة **منتهية** → «متابعة — دفع» → شاشة الدفع (مع حارس الدفعة المعلّقة).

### ز) الرسائل المتفائلة (م14)
- كل رسالة تظهر فوراً بحالة «جارٍ الإرسال» → «تم الإرسال/تمت القراءة» أو
  «فشل + إعادة محاولة» — لا رسائل تختفي بلا أثر.

# 🔍 ملحق 2026-08-19 — تحليل التغطية (نتيجة التدقيق في الكود)

**تصحيح جوهري:** إنشاء جلسة التجديد (`renewal ready`) + رسالة system + إشعار
المحامي تتم **داخل `approve_payment_final_v3`** (سلسلة الاعتماد الفعلية
`admin → v5 → v4 → v3`) — وليس في تريغر الدفعات. نسخة سابقة من هذا الإصلاح
أضافت المنطق نفسه في التريغر (ازدواج)؛ صُحّح بحذف التكرار وإبقاء إصلاح ref_id.

## ثغرات اكتُشفت في تحليل التغطية وعولجت

| # | الثغرة | الحالة قبل | الحالة بعد |
|---|---|---|---|
| 1 | ref_id إشعار «تم اعتماد التجديد» للمستخدم | ref=payment_id ⇒ الضغط يفتح محادثة غير موجودة | ref=المحادثة الأم (تريغر) |
| 2 | حارس الدور في الموجه | المستخدم ممنوع من إشعار الاعتماد (guard محامٍ فقط) | سماح المستخدم ⇒ فتح المحادثة |
| 3 | «المحادثات السابقة» تعتمد الحقول القديمة | chat_duration لا يمدّده V2 ⇒ «منتهية» رغم جلسة حية ⇒ دفع مكرر | `has_live_session` من السيرفر ⇒ «متابعة المحادثة» |
| 4 | دفع التجديد يمرر لاستشارة جديدة | `_hasApprovedPaymentFor` يتجاهل continue_chat ⇒ إرسال يفشل سيرفرياً | استثناء continue_chat (بطاقته الخاصة تبقى) |
| 5 | مسار phone_renew بلا حارس دفعة معلّقة | إمكانية إنشاء دفعة تجديد ثانية أثناء انتظار الأولى | `_guardPending(0)` في _initialize |
| 6 | استطلاع الشات لا يغطي 'ready' | لو فشل Realtime يعلق على «بانتظار المحامي» | يشمل 'ready' |

## الحالات المؤكدة مغطاة (من الشجرة الأصلية)
- دفع مكرر ممنوع (حارس لكل مسارات الدفع بعد الإصلاح).
- رفض الدفعة → إشعار + بطاقة سبب + إعادة محاولة (نفس المحادثة).
- عكس الاعتماد → إلغاء الجلسة (فقط إن كانت 'ready').
- انتهاء مهلة الدقيقتين → بدء تلقائي + إشعار.
- محادثة أقدم من 7 أيام → ممنوع التجديد (CHAT_EXPIRED_7DAYS).
- المحامي لا يستأنف → تبقى ready بلا عداد (وقته لا يُحتسب).
- استشارة جديدة → دفعة بلا continue_chat → إسناد محامٍ جديد.
