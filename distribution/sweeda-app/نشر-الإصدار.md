# 🚀 خطوات نشر إصدار جديد على المستودع العام (دليل المالك)

> هذا الملف داخل المستودع الخاص — دليل تشغيلي لكل مرة تطلق فيها إصداراً.
> المستودع العام: `hady-albnnai/sweeda-app` (صفحة التحميل + الإصدارات + الصفحات القانونية)

---

## أول مرة فقط — إنشاء المستودع العام (10 دقائق)

1. افتح: **github.com/new**
   - Repository name: `sweeda-app`
   - Visibility: **Public** ⚠️ (خاص = ما حدا بيقدر ينزل!)
   - لا تفعّل «Add a README» (عندنا ملف جاهز)
   - Create repository
2. من جهازك (في مجلد المشروع الخاص):
   ```cmd
   cd distribution\sweeda-app
   git init
   git add .
   git commit -m "صفحة التحميل الرسمية + الصفحات القانونية"
   git branch -M main
   git remote add origin https://github.com/hady-albnnai/sweeda-app.git
   git push -u origin main
   ```
3. فعّل الصفحات القانونية (Pages):
   - بالمستودع العام: **Settings ← Pages**
   - Source: **Deploy from a branch** ← Branch: `main` ← Folder: `/ (root)` ← Save
   - بعد دقيقة: `https://hady-albnnai.github.io/sweeda-app/legal/privacy-policy.html` يشتغل
4. شغّل Migration تجهيز الإصدار (من مجلد المشروع الرئيسي):
   ```cmd
   powershell -ExecutionPolicy Bypass -File scripts\deploy_supabase.ps1 -PAT "<توكنك الجديد>" -REF "vsgkgnjtebjxyqwpuopz" -SkipCleanup -SkipFunctions
   ```
   (يشغّل `2026_08_28_release_preparation.sql` → يفعل فاحص التحديث + الروابط القانونية الجديدة)

## كل إصدار جديد (الروتين الكامل)

### 1) التوقيع — أول مرة فقط: توليد المفتاح (واحتفظ به للأبد! ⚠️)
```cmd
keytool -genkey -v -keystore %USERPROFILE%\sweeda-release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias sweeda
```
- احفظ كلمة سر المفتاح + انسخ ملف `.jks` **لمكانين آمنين** (فقدانه = استحالة تحديث التطبيق للجميع!)
- أنشئ ملف `android\key.properties` في المشروع:
  ```properties
  storePassword=<كلمة سر المخزن>
  keyPassword=<كلمة سر المفتاح>
  keyAlias=sweeda
  storeFile=C:\\Users\\ASUS\\sweeda-release.jks
  ```
  (المسار بخطين مائلين \\ — والملف مستثنى من Git تلقائياً)

### 2) البناء
```cmd
flutter build apk --release
```
الناتج: `build\app\outputs\flutter-apk\app-release.apk`

### 3) البصمة الأمنية (SHA-256)
```cmd
certutil -hashfile build\app\outputs\flutter-apk\app-release.apk SHA256
```
انسخ الناتج.

### 4) فحص VirusTotal
- افتح **virustotal.com** ← ارفع ملف الـ APK ← انتظر الفحص
- انسخ رابط التقرير من شريط العنوان
- ⚠️ قد تظهر 1-3 «إنذارات» من محركات غير معروفة — طبيعي لتطبيقات جديدة، سمعتها تتحسن مع الإصدارات. اشرح ذلك بثقة إن سُئلت.

### 5) رفع الإصدار على المستودع العام
- بالمستودع العام: **Releases ← Draft a new release**
- Tag: `v1.1.0` (مطابق لإصدار pubspec بدون +11)
- Title: `الإصدار 1.1.0`
- الوصف: أبرز الجديد (انسخ من سجل الإصدارات بـ README)
- **Attach files** ← ارفع `app-release.apk` (بنفس الاسم حرفياً!)
- Publish release

### 6) تحديث صفحة التحميل (README بالمستودع العام)
- سجل الإصدارات: أضف سطر الإصدار الجديد
- البصمة: حدّث خانة SHA-256
- VirusTotal: حدّث الرابط

### 7) تفعيل التنبيه لكل الأجهزة (أهم خطوة!)
من التطبيق (كمدير): **الإعدادات ← «أحدث إصدار منشور (فاحص التحديث)»** ← اكتب `1.1.0` (أو رقم الإصدار الجديد) ← حفظ
← من اللحظة التالية: كل جهاز يفتح التطبيق بتظهرلو نافذة «تحديث جديد متوفر» مع زر تحميل مباشر 🔄

## ⚠️ قواعد ذهبية
1. **مفتاح التوقيع مقدس** — نفس المفتاح لكل الإصدارات، نسخة احتياطية بمكانين
2. **versionCode تصاعدي دائماً** (11، 12، 13...) بـ pubspec.yaml
3. **اسم ملف الـAPK ثابت دائماً**: `app-release.apk` (الرابط الثابت latest/download يعتمد عليه)
4. أي نسخة التطبيق من مصدر غير هذا المستودع = غير موثوقة
